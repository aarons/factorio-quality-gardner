Version: 0.2.0
Date: 28. 07. 2026
  Features:
    - Ghost provisioning: when a ghost requests a quality the network does not stock, the ghost is
      retargeted to the best quality the network does have - even a lower one - so the building
      gets built instead of waiting forever. Once built, it is an ordinary upgrade candidate and
      is raised back up as better stock appears. Always on.
  Changes:
    - Removed the hidden-quality startup settings (skip and sticky). Every quality reachable from
      normal is treated alike; special handling for other mods' hidden qualities may return once
      the core is proven.
    - Rewrote the engine as a stateless scan: each logistic network is visited round-robin, its
      contents are read fresh, and its roboport coverage is scanned for upgrade candidates. No
      per-entity state is kept anywhere, so nothing can get out of sync with the world.
    - Existing upgrade marks (the mod's, the player's, or another mod's) now count as demand
      against network supply, so the same item is never promised twice.
    - The mod no longer cancels any upgrade order: starved orders pend with the vanilla
      missing-material alert until supply reappears or a player clears them. The order timeout
      setting is gone.
    - Upgrades now behave exactly like player-ordered native upgrades; the special restore of
      accumulator charge, lamp always-on, and rocket silo auto-launch is gone.
    - Settings reworked: "Entities per tick" is now "Entities per pass" (work per 10-tick slice),
      and a new "Round delay" rest between rounds gives bots time to pick up ordered items.

Version: 0.1.0
Date: 17. 07. 2026
  Features:
    - Initial release. Buildings are marked for upgrade when higher-quality versions of them sit
      in the logistic network's storage chests, and construction bots swap them out.
    - Worst-quality buildings are upgraded first, straight to the best quality on hand.
    - Orders that starve (supply taken by players, blueprints, or other demand) are automatically
      cancelled after a configurable timeout, keeping alerts clean.
    - Processing is spread evenly across ticks (configurable work per tick) instead of burst
      scans, and each network only receives as many orders as it has construction robots
      available.
    - Supply reserve and order timeout settings.
